TheseWarum das zählt

Fast nichts. Aber kein Spielzeug.

Kleine Linux-Images gibt es seit Jahrzehnten. Die meisten sparen, indem sie etwas weglassen: das Netzwerk, die Fernwartung oder die Möglichkeit, Software nachzuladen. Dann ist die VM klein und taugt zu nichts.

Quark Linux geht anders vor. Es liefert nur das mit, was man braucht, um sich alles Weitere zu holen: einen Kernel, eine Shell, eine Netzwerkverbindung, einen SSH-Server und einen Paketmanager. Programme sind nicht installiert. Sie werden geholt, wenn man sie braucht, und danach wieder entfernt.

Ein Kernel, eine Shell, eine Leitung nach draußen. Der Rest ist ein Befehl.

Der Kernel ist das Gewicht

BusyBox und Dropbear sind hier einzeln komprimiert gemessen. Im initramfs werden sie gemeinsam komprimiert, daher ist die Summe der Einzelwerte größer als 313 KB. Entpackt ist das Root-Dateisystem 834 798 B groß.

Weiter schrumpfen heißt, das Netzwerk oder SSH zu opfern. Dann kann die VM nichts mehr nachladen.

Nichts installiert. Alles verfügbar.

Der Befehl q holt ein Paket samt Abhängigkeiten, führt es aus und löscht es wieder. Die VM bleibt so klein, wie sie gestartet ist. Beim Start ist apk bewusst noch gar nicht vorhanden. Der Download wird per sha256-Prüfsumme gegen einen festen Wert geprüft.

Der Kernel startet ohne PCI und ACPI. Die virtuelle Netzwerkkarte hängt direkt am virtio-mmio-Bus. Das spart rund 100 KB. Weitere 120 KB sparten entfernte Systemaufrufe und Netzwerkoptionen. Insgesamt schrumpfte der Kernel von 1 439 376 auf 1 288 336 Byte.

DefinitionWas „brauchbar“ heißt

Der Rekord, sauber definiert

Ein Rekord braucht eine Regel. Quark Linux gilt als brauchbar, wenn die VM alle vier Punkte erfüllt:

KriteriumNachweis
Startet und liefert eine ShellTest „Boot“, 3,6 s
Hat Netzwerk (DHCP)Test „DHCP“
Ist per SSH erreichbarTest „SSH-Banner“
Kann beliebige Programme nachladen und wieder entfernenTest „q jq:jq“ und „Clean-up“

Unter diesen vier Bedingungen ist Quark Linux mit 1,6 MB die kleinste VM, die mir bekannt ist. Die Aussage gilt, bis jemand eine kleinere vorlegt.

GrenzenWas Quark nicht ist

Wo die Zahl endet

  • Verwandte Arbeiten existieren. Tiny Core, iPXE, netboot.xyz und die minimalen Images für Firecracker sind teils ähnlich klein. Sie bieten aber nicht dieselbe Kombination aus SSH und Paketinstallation auf Abruf. Eine systematische Recherche steht noch aus.
  • Nur für QEMU microvm. Das Image bootet nicht auf der Standardmaschine pc. Die Option acpi=off ist nötig, sonst sieht der Gast keine Netzwerkkarte.
  • Nachladen braucht Internet. q holt Pakete aus dem Alpine-Repository. Ohne Verbindung läuft nur, was schon da ist.
  • Kein Produktivsystem. Root hat ein leeres Passwort, erreichbar nur über die lokale Weiterleitung, sofern kein Schlüssel eingebaut wird. Der Kernel ist auf Größe getrimmt, ohne zusätzliche CPU-Schutzmaßnahmen wie Retpoline. Nichts bleibt nach dem Neustart erhalten.
  • WLAN ist ungetestet. wifi existiert für echte Hardware mit Treiber, wurde aber nicht geprüft.
NachbauAlles aus dem Quelltext

# bauen: Docker, mehrstufig, Ergebnis in dist/

# ohne Skript
$ qemu-system-x86_64 -machine microvm,acpi=off -nodefaults -m 128 \
    -kernel dist/vmlinuz -initrd dist/initramfs.cpio.xz -append console=ttyS0 \
    -netdev user,id=n,hostfwd=tcp:127.0.0.1:2222-:22 \
    -device virtio-net-device,netdev=n -display none -serial stdio
